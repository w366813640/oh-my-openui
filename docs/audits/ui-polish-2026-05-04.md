## Findings

1. Narrow viewports need a real shell strategy.
   The sidebar keeps its 240px expanded width at mobile sizes. On a 390px viewport, the main content becomes clipped horizontally instead of collapsing to an icon rail, drawer, or single-column layout. Artifact mode is the most severe case because the sidebar, thread, and artifact pane all compete for the same narrow viewport.

2. Artifact mode needs stronger responsive behavior.
   With the artifact pane open, the message column collapses into a very narrow strip. User bubbles and composer controls wrap awkwardly, while the artifact toolbar remains readable. The grid should prioritize either the artifact pane or the thread at narrow widths, not show both at unusable sizes.

3. Light theme surface hierarchy is too soft.
   Background, sidebar, cards, chat bubbles, and input surfaces are close in value. The result is warm, but panels do not always read as intentional layers. Borders and shadows need a slightly clearer ladder so the UI remains calm without becoming blurry.

4. Dark theme contrast is readable but heavy.
   The dark palette has good legibility, but large regions share a similar near-black value. Sidebar, main canvas, composer, code blocks, and artifact background can use a more precise contrast ladder and a quieter border color.

5. Composer is visually important but slightly buried.
   The sticky composer has the right structure, but its glassy background and low-contrast controls make it feel less anchored than the main action surface. Attachment, tuning, chip, model, and send states should have clearer affordance without increasing visual noise.

6. Sidebar active and grouped states can be more polished.
   Navigation states work, but selected items, section labels, recent links, and account footer are very flat. The active rail is useful, but it could be integrated with a softer selected fill, better hover state, and more consistent icon/text contrast.

7. Message content needs richer scan points.
   Assistant content is readable, but quoted tips, ordered lists, code blocks, artifact cards, and streaming states could use more differentiated spacing and surface treatment. This would make long threads easier to scan without turning messages into heavy cards.

8. Modal and floating surfaces are close but uneven.
   The modal shape and backdrop work well. Focus ring, text fields, and button treatments should be normalized with the rest of the system tokens so dialogs, dropdowns, tooltips, toasts, and popovers feel like one family.

9. List and project pages are clean but sparse.
   The list layouts are functional, though row surfaces, search bars, bulk selection, and empty rail cards need more product-grade density and feedback states. They should feel like a finished app surface, not only a layout sample.

10. Demo content needs stronger product narrative.
    The current fixtures demonstrate components, but they repeat similar pet-related copy and do not cover enough real product states. Add longer conversations, more varied artifacts, clearer project data, connector/status rows, empty states, and error/warning examples.

## Implementation Targets

- Foundation pass: improve token contrast, border, shadow, focus, hover, and text hierarchy in `packages/tokens` and `packages/ui/src/styles.css`.
- Core component pass: polish Sidebar, Composer, MessageList, ArtifactPane, Modal, Toast, Tooltip, and shared primitive states.
- Demo pass: expand playground data and routes so the first launch reads like a coherent product sample.
- Responsive pass: at minimum, prevent broken narrow layouts by collapsing shell regions and avoiding simultaneous sidebar/thread/artifact squeeze.
